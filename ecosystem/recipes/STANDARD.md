# Titan Recipe Standard

**النسخة:** 0.1 — مسودة للمراجعة
**تاريخ:** 2026-07-27

---

## الفلسفة

Titan يضع الحدود. المجتمع يبني.

هذه الوثيقة تُعرِّف الحدود الأساسية فقط. كل ما هو خارجها — هيكل الملفات، أسلوب التوثيق، طريقة الاختبارات — قرار صاحب الوصفة.

> إذا أمكن حذف الوصفة من المشروع دون الحاجة لتعديل Titan أو تغيير أي Core code، فهي Recipe صحيحة.
> إذا احتاجت إلى تعديل Titan نفسه، فهي Feature Proposal — لا Recipe.

---

## ما هي الوصفة؟

وصفة Titan هي حزمة Python تُغلّف نمط معالجة شائعاً باستخدام Titan Core APIs، وتُقدّمه في شكل كائن قابل للاستدعاء.

الوصفة لا تُنشئ سلوكاً عند الاستيراد. المطور يستورد، يُهيّئ، يُسجّل — كل خطوة صريحة في كوده.

```python
from titan_recipe_antiflood import AntiFlood

flood = AntiFlood(limit=5, window=10)

@bot.on("message")
async def handle(ctx):
    await flood(ctx)
```

## التسمية

الاتفاقية الرسمية الموصى بها:

| | الشكل |
|---|---|
| اسم الحزمة | `titan-recipe-<name>` |
| اسم الاستيراد | `titan_recipe_<name>` |

من يتبع هذه الاتفاقية تصبح وصفته قابلة للاكتشاف تلقائياً — بحث `titan-recipe` على PyPI يعطي كل الوصفات المتاحة. من أراد تسمية مختلفة فذلك قراره، لكنه يتحمل مسؤولية الاكتشاف بنفسه.

---

## التوزيع

Titan لا يفرض وسيلة توزيع. استخدام PyPI هو التوصية الافتراضية لأنه الأكثر شيوعاً — لكن مستودع GitHub أو مرآة داخلية أو أي وسيلة أخرى تؤدي الغرض ذاته.

```
pip install titan-recipe-<name>
```

---

## الحدود مع Titan

الوصفة تستخدم فقط ما هو مُعلَن في CONTRACT.md ضمن Public API:

- `@bot.on(...)` لتسجيل handlers في كود المطور
- أي خاصية أو action في `ctx`
- `bot.middleware()` — بإذن صريح من المطور، لا تلقائياً
- `bot.telegram.*`
- النماذج المُصدَّرة: `Sender`، `Chat`، `Message`، `Update`

---

## ما هو ممنوع

هذه حدود معمارية، لا توصيات:

**لا تعديل على Context:**
لا إضافة خصائص أو دوال جديدة على `ctx` أو أي كلاس في `titan.*`.

**لا تسجيل تلقائي عند الاستيراد:**
لا middleware يُسجَّل تلقائياً، لا شيء يحدث خلف الكواليس.

**لا وصول للـ internals:**
أي شيء يبدأ بـ `_` في `titan.*` هو implementation detail — الوصفة لا تعتمد عليه.

**لا monkey-patching:**
لا تعديل على كلاسات Titan أو سلوكها في وقت التشغيل.

**لا حالة خفية:**
إذا كانت الوصفة تحتاج تخزيناً بين الـ updates، يُمرّره المطور صراحةً — لا تُنشئ الوصفة storage مخفياً.

## الفرق عن الوصفات الرسمية

| | رسمية | مجتمعية |
|---|---|---|
| مسار الاستيراد | `from titan.recipes import X` | `from titan_recipe_<name> import X` |
| الصيانة | فريق Titan | صاحب الحزمة |
| الاستقرار | مُجمَّد بعد النشر | semver |

القواعد المعمارية واحدة في الحالتين. الاختلاف في الملكية، لا في الحدود.

## التوافق مع إصدارات Titan

في `pyproject.toml`:

```toml
[project]
dependencies = ["titan>=1.0,<2.0"]
```

pip يحل التوافق تلقائياً — لا آلية خاصة مطلوبة.
