# 021 — Template System

**Status:** Accepted

---

## Proposal

تعريف "Template" كمفهوم رسمي في Titan — مختلف عن Example ومختلف عن Recipe —
وإنشاء معيار يُنظِّم القوالب الرسمية والمجتمعية.

---

## Context

Titan لديها:
- `examples/` — أمثلة تُوضِّح ميزات محددة
- `titan.recipes` — أنماط قابلة للتثبيت كـ dependency
- `/ecosystem` — طبقة تُعرِّف كيف يبني المجتمع حول Titan

لكن لا يوجد مفهوم رسمي لـ "نقطة البداية" — مشروع كامل يأخذه المطور ويبني فوقه مباشرة.
هذا ما يسدّه Template System.

الفرق الجوهري عن Example: Example يُعلِّم فكرة ويبقى في المستودع. Template يُمكِّن
مشروعاً ويُصبح ملك المطور بعد النسخ. الهدف مختلف، المصير مختلف.

الفرق الجوهري عن Recipe: Recipe اعتمادية تُضيفها لمشروع قائم. Template هو نقطة البداية
التي ستُضيف إليها Recipes لاحقاً.

---

## Decision

### ١. تعريف Template

قالب Titan هو مشروع بوت كامل، جاهز للتشغيل فور نسخه، مُصمَّم ليصبح ملك المطور.

اختبار الليتماس: إذا استطاع المطور نسخ القالب، تعيين `BOT_TOKEN`، وتشغيل البوت
مباشرة — فهو Template صحيح.

### ٢. القوالب تعيش خارج هذا المستودع

كل قالب مستودع GitHub مستقل — رسمياً كان أم مجتمعياً.

هذا المستودع يحتوي المعيار فقط (`ecosystem/templates/STANDARD.md`).
لا قوالب فعلية داخل مستودع Titan في هذه المرحلة.

**السبب:** مستودع Titan مسؤول عن Core والمعايير. قالب كامل داخله يعني:
- ملفات مشروع كاملة تحتاج صيانة مستقلة عن Titan
- إصدارات القالب مرتبطة بإصدارات Titan بدون مبرر
- مشروع "حي" داخل مستودع مكتبة

القوالب ككيانات مستقلة تُصدر نسخها بشكل مستقل — هذا يخدم المطور أكثر.

### ٣. اتفاقية التسمية

`titan-template-<name>` للمستودعات على GitHub.

نفس المنطق الذي أثبت نجاحه مع `titan-recipe-<name>`: الاتفاقية هي البنية التحتية.
GitHub search: `titan-template` يُعطي كل القوالب المتاحة بدون registry مخصص.

### ٤. نموذج التوزيع

Titan لا يفرض وسيلة توزيع. الشرط الوحيد: المطور يحصل على نسخة كاملة من
المشروع يملكها بالكامل. أي وسيلة تحقق هذا مقبولة — مستودع Git قابل للاستنساخ،
GitHub Template Repository، أرشيف مضغوط، أو غيرها. الاختيار قرار صاحب القالب.

لا CLI، لا `titan new`، لا أداة توليد من أي نوع.

### ٥. الموقع في /ecosystem

```
ecosystem/
└── templates/
    └── STANDARD.md    ← المعيار فقط
```

---

## Rule

قوالب Titan تعيش خارج مستودع Titan. هذا المستودع يعرِّف المعيار، لا المحتوى.
أي قالب يحتاج أن يعيش داخل هذا المستودع هو مشروع مُضاف — وإضافته تحتاج ADR مستقلاً.

---

## Alternatives Considered

**قوالب داخل `/ecosystem/templates/official/`:**
سيُبقي كل شيء في مكان واحد لكنه يُحوِّل مستودع Titan تدريجياً إلى مجموعة مشاريع
كاملة تحتاج صيانة مستقلة. رُفض لأن الفصل بين "يُعرِّف المعايير" و"يحتوي المشاريع"
أكثر قيمة من مركزية الملفات.

**أداة CLI (`titan new <template-name>`):**
تُوفِّر تجربة أفضل لكنها تعني بناء وصيانة CLI قبل أن يثبت النظام نفسه.
رُفض — البساطة أولاً، والأداة لاحقاً إذا ثبتت الحاجة الفعلية.

---

## Consequences

**ما يُكتسب:**
- مفهوم رسمي لـ Template يُميّزه عن Example وRecipe
- المجتمع يملك نمطاً واضحاً لبناء ونشر القوالب
- مستودع Titan يبقى مسؤولاً عن المعايير لا عن تشغيل مشاريع متعددة

**القيود المقبولة:**
- لا يوجد قالب رسمي تشغيلي الآن — الجهة تحتاج إنشاء مستودع منفصل عند الحاجة
- الاكتشاف يعتمد على اتفاقية التسمية لا على أداة مخصصة

**ما يبقى خارج نطاق هذا القرار:**
- محتوى أي قالب رسمي — يُقرَّر عند إنشاء أول مستودع `titan-template-*`
- قائمة رسمية بالقوالب المعروفة — تُضاف لاحقاً كجدول في STANDARD.md إذا احتيج إليها
- أداة اكتشاف أو CLI — مؤجَّلة لما بعد ظهور قوالب فعلية
